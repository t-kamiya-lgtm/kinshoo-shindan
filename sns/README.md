# PROTEIN MONSTER｜SNS投稿ダッシュボード

高タンパク麺「PROTEIN MONSTER / SOVA」の Instagram・X 向けフィード投稿を、
画像・キャプション・ハッシュタグまで自動生成し、薬機法／景表法チェックを通してから
書き出すためのダッシュボードです。

ビルド不要の静的サイトです。`sns/index.html` を開けば動きます。

- 公開URL（GitHub Pages）… `https://<ユーザー名>.github.io/kinshoo-shindan/sns/`
- ローカル確認 … リポジトリ直下で `python3 -m http.server 8000` → http://localhost:8000/sns/

---

## 1. 最初にやること（初回だけ）

1. [Drive の素材フォルダ](https://drive.google.com/drive/folders/1uXFEWTMOK9SUzummPzaUfwp61pcEpenl)
   をダウンロードする。
2. ダッシュボードの **画像ライブラリ** タブを開き、解凍したフォルダの画像をまとめてドラッグ＆ドロップする。
   ファイル名でカタログと自動照合されます。
3. 各画像にタグを付ける。これが提案の精度を決めるので、ここだけは手を動かす価値があります。
   - **商品** … その写真に写っているのがどちらの SKU か（`両方／共通` も可）
   - **シーン** … 調理後／乾麺／パッケージ／調理中 など
   - **文字を載せる余白** … 上に余白／下に余白／余白なし

### 同じ名前の画像を取り込んだとき

**既にある画像と同名のファイルが含まれていると、取り込む前に確認のダイアログが出ます。**
黙って上書きすると元の画像が失われるためです。選べるのは次の4つ。

| 選択 | 動き |
| --- | --- |
| やめる（ファイル名を直す） | 何も取り込まずに中止。ファイル名を変えてから入れ直す |
| 重複した名前をコピー | 重複したファイル名の一覧をクリップボードへ。エクスプローラーで直すとき用 |
| 重複を飛ばして取り込む | 同名は既存を残し、新規ぶんだけ取り込む |
| 上書きして取り込む | 同名を差し替える（タグは残ります） |

同じ選択の中に同名が2つ含まれている場合も重複として扱います。

画像はこの端末のブラウザ内（IndexedDB）にだけ保存されます。どこにもアップロードされません。
別の端末で使うときは、その端末でもう一度取り込んでください（タグは **設定 → 書き出し／読み込み** で移せます）。

> **なぜ Drive から直接読まないのか**
> Drive の画像を `<canvas>` に描くと CORS でタイントし、合成画像を書き出せなくなります。
> ローカルから取り込む方式にしているのはこのためです。

## 2. 毎日の使い方

1. 毎朝 8:00（JST）に、その日の提案の要点がメールで届きます。
2. メールのボタンからダッシュボードを開くと、**Instagram 1本・X 1本**の提案が並んでいます。
   提案は日付をシードに生成されるので、**メールと画面の内容は必ず一致します**。
3. 直したいところを直す。
   - キャプション／ハッシュタグはその場で編集でき、編集内容は自動保存されます。
   - 写真を変える（`別の写真` / プルダウン）、文字合成のオンオフ、書き出し比率も切り替えられます。
   - **画像をクリックすると別ウインドウで等倍表示**されます。書き出す画像とまったく同じものです。
   - 気に入らなければ `別案を出す`（訴求軸ごと入れ替わります）。
4. 法令チェックが緑になったら **`画像をダウンロード`** と **`キャプション＋タグをコピー`**。
5. X は `Xの下書きを開く` で本文入りの投稿画面が開きます（画像は手動添付）。
   Instagram はアプリ／Web で画像を添付し、キャプションを貼り付けてください。
6. 投稿したら `投稿する` を押すと **投稿ログ** に記録され、何をいつ出したかが残ります。

## 3. 生成のしくみ

```
日付 → 訴求軸のローテーション → SKU 決定 → フック / 本文 / 締め / タグ / 画像プラン
                                              ↓
                                    薬機法・景表法チェック
```

- **訴求軸**は 4つを日替わりでローテーションします。
  筋トレ・ボディメイク／置き換え・栄養設計／時短・アレンジレシピ／安心設計・原材料。
- **SKU** はどちらか一方に特化させます（1投稿に両方を混ぜません）。
- **Instagram と X は既定で「同じ投稿の媒体別バージョン」**になります。訴求軸・SKU・書き出し・
  画像の文字・写真が一致し、X だけ本文を短く・タグを少なくします。
  内容の重複をコントロールしたいときはこのまま、別々の話題を2本出したいときは
  **設定 → Instagram と X の関係** をオフにしてください。
- **画像**は「写真＋文字合成」と「写真そのまま」を約50:50でランダムに振ります。
  合成の見た目は公式アカウントの投稿デザインに合わせた3つの型から選ばれます。

| 型 | 見た目 | 主に使う軸 |
| --- | --- | --- |
| `stat` 数値主役 | オレンジの帯に極太数字（「31.7g の衝撃を。」） | 筋トレ／置き換え |
| `hook` コピー主役 | 見出し2行＋アクセントの縦線 | 時短・レシピ |
| `band` 上下帯 | 上にロゴ帯、下にコピー帯。パッケージ的な統一感 | 安心設計 |

どの型にも共通で、左上にロゴロックアップ（PROTEIN 白／MONSTER オレンジ）、
オレンジの角丸ラベル、下部にスペックのチップ3つが入ります。
型・ラベル・見出しはカードごとに切り替え・編集でき、`文字を戻す` で自動生成の状態に戻ります。
文字は**上／下のどちらに置くかも選べます**。上に置くとロゴが自動で下に回ります。
- 乱数は日付から決まる決定的な擬似乱数です。同じ日付なら誰がどこで開いても同じ提案になります。

## レシピ投稿（4枚組）

`レシピ投稿` タブで、1レシピを Instagram のカルーセル4枚として書き出します。

| 枚 | 内容 |
| --- | --- |
| ① | できあがり写真＋黒ラベル（一部オレンジ）＋白の大見出し＋「スワイプでレシピをチェック」 |
| ② | オレンジ帯の見出し＋クリーム地の材料表＋ロゴ |
| ③ | `RECIPE` の見出し＋調理時間バッジ＋番号つき手順 |
| ④ | 黒地に `THANK YOU FOR READING`、案内ボックス、他レシピのサムネ3枚、保存の誘導 |

4枚とも 1080×1350（4:5）で揃えています。カルーセルは全枚同じ比率でないと
Instagram 側でトリミングされるため、ここは固定です。

`4枚すべてダウンロード` を押すと `M25_1_title.jpg` 〜 `M25_4_outro.jpg` の順に
書き出されます。**その番号順に並べて投稿してください。**

原稿24本（モンスター14本・ソバ10本）を収録済みです。キーは `M`＋番号／`S`＋番号で、
モンスターとソバで番号が重複していても衝突しません。

### レシピを追加する

`data/recipes.js` に原稿を写します。既存の1件をコピーして中身を差し替えるのが早いです。
原稿（Word）の見出しとフィールドは次のように対応します。

| 原稿 | recipes.js |
| --- | --- |
| `25# 喫茶店風！玉ねぎとケチャップの…` | `key` / `no` / `label` / `title` |
| `## 概要` の【…】行 | `summaryLead` |
| `## 概要` の本文 | `summary` |
| `- 目安時間：5分` | `minutesBase`（前提のゆで時間は `boilBase`） |
| `## 材料（1人前）` | `ingredients`（`k` 品目 / `v` 分量） |
| `## 作り方` | `steps` |
| `## 栄養成分およびPFCバランス` | `nutrition` |

`label` のうちオレンジにしたい文字を `labelAccent` に書きます（例：`喫茶店`）。
`title` の改行位置は `\n` で指定します。①と②の見出しはこの改行をそのまま使います。

栄養値は**1皿ぶんの推定値**です。麺そのものの分析値とは別物なので、
キャプションには推定値であることと麺単体の値の両方が自動で入ります。

### ゆで時間の換算

モンスター版の原稿は「ゆで3分」、ソバ版は「ゆで5分」を前提に書かれていますが、
商品表示はどちらも「3〜5分」です。そこで、

- 手順の中のゆで時間は **`{boil}` と書いておく**と、表示時に `3〜5` へ差し替わります
- 調理時間は `minutesBase - boilBase + 5` で換算されます（例：原稿5分・ゆで3分前提 → **約7分**）

画像とキャプションは同じ換算結果を使うので、両者の数字がずれることはありません。

### 使い回しを避けるしくみ

投稿ログを見て、次の2つを避けます。写真の枚数が少ないうちは同じ絵が短期間で繰り返し出てしまうため、その対策です。

- **直近14日に投稿した写真は選ばれません**（候補が尽きた場合のみ全体から選び直します）
- **直近30日に同じ書き出しを使っていると、カードに「書き出し重複」の注意が出ます**

画像ライブラリでは各写真に使用回数が表示され、`未使用` フィルタで一度も使っていない写真だけを絞り込めます。
ログはこのブラウザに保存されるため、この判定も端末ごとになります。

### 数値の出どころ

キャプション中の数値は**すべて `sns/data/products.js` から差し込まれます**。
スペックが変わったらこのファイルだけを直せば、全文面に反映されます。文面側に数値をベタ書きしないでください。

## 4. 薬機法・景表法チェック

`sns/compliance.js` が本文・ハッシュタグ・**画像に載せる文字**の3つを検査します。

| レベル | 挙動 |
| --- | --- |
| **要修正（block）** | 投稿ボタンが押せません |
| **要確認（warn）** | 押せますが、指摘内容を確認してください |

主な検出対象:

- **薬機法** … 痩身・脂肪燃焼、筋肉増強、疾病の治療／予防、免疫・代謝・整腸などの身体機能への作用、効果を暗示する体験談
- **景表法** … No.1・最上級表現、「必ず」「100%」等の断定、「〜だけで」、二重価格、出典のない比較
- **食品表示基準** … 「糖質ゼロ」「糖質オフ」等、基準を満たさない強調表示

比較表現（「より多い」「約半分」等）を使った場合、本文に出典注記
（`※当社調べ` / `※日本食品標準成分表2021年版（八訂）`）がなければ **要修正に格上げ**されます。

> このチェッカーは機械的な足切りです。最終的な表現の可否はご判断ください。
> 検出語を足したいときは `compliance.js` の各ルール配列に追記します。

## 5. 毎朝のメール

`.github/workflows/daily-sns-brief.yml` が毎日 23:00 UTC（= 8:00 JST）に動きます。

送信するにはリポジトリの **Settings → Secrets and variables → Actions** に以下を登録してください。
未登録のうちは送信ステップがスキップされ、本文は Actions の成果物（`brief.html`）として残ります。

| 種別 | 名前 | 例 |
| --- | --- | --- |
| Secret | `MAIL_SERVER` | `smtp.gmail.com` |
| Secret | `MAIL_PORT` | `465` |
| Secret | `MAIL_USERNAME` | 送信元アドレス |
| Secret | `MAIL_PASSWORD` | アプリパスワード（通常のログインパスワードではありません） |
| Secret | `MAIL_TO` | 受信先アドレス（カンマ区切りで複数可） |
| Variable | `DASHBOARD_URL` | `https://<ユーザー名>.github.io/kinshoo-shindan/sns/` |

`DASHBOARD_URL` を設定しない場合は GitHub Pages の既定URLが自動で組み立てられます。
独自ドメインや別の場所で公開している場合だけ設定してください。

手動で試すときは Actions タブから `workflow_dispatch` で実行できます（日付を指定可）。

## 6. 文面を育てる

フック・本文・締め・ハッシュタグ・画像コピーはすべて `sns/data/copy.js` にあります。
追記したら**必ず**自己診断を回してください。365日 × 4変奏 × 2媒体を総当たりし、
法令チェックと文字数上限を全件検査します。

```bash
node sns/selftest.js
```

このコマンドは朝メールのワークフローでも毎日実行されるため、
法令チェックに触れる文面が混ざるとメール配信前に失敗して気づけます。

## 7. 実投稿の自動化について

現在は「生成 → 確認 → 書き出し → 各アプリに貼る」という半自動運用です。
ボタン一つで実投稿まで行うには、別途以下が必要になります。

- **Instagram** … Facebook ページに連携したプロアカウント、Meta 開発者アプリ、Instagram Graph API の審査通過、
  および画像を公開URLでホストする場所（Graph API は画像をURLで受け取る仕様のため）
- **X** … X API の有料プラン（メディア添付を伴う投稿には Basic 以上が必要）

いずれもトークンを保持するサーバー側が要るため、静的サイトのままでは実現できません。
必要になった段階で、この生成エンジン（`sns/engine.js`）はそのまま流用できます。

## 8. ファイル構成

```
sns/
  index.html        画面
  app.js            UI・状態管理
  engine.js         提案の生成（ブラウザ／Node 共用）
  compliance.js     薬機法・景表法チェック
  composer.js       canvas への画像合成・書き出し
  library.js        画像ライブラリ（IndexedDB）とタグ、画像の自動選択
  recipe.js         レシピ投稿の4枚組を描く
  selftest.js       生成物の総当たり検査
  data/
    products.js     商品スペック（数値の唯一の出どころ）
    copy.js         フック・本文・締め・タグ・画像コピー
    images.js       Drive 素材のカタログとタグ語彙
    recipes.js      レシピ原稿
scripts/
  daily-brief.mjs   朝メールの本文を組み立てる
.github/workflows/
  daily-sns-brief.yml  毎朝 8:00 JST の実行
```
